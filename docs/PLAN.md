# VMW Refactor Plan

**Goal:** Make VMW reproducible, verifiable, and maintainable without rewriting the battle-tested bash core. The patches + SMBIOS generator are the crown jewels — the scripts around them get hardened.

**Status:** All phases implemented. See each phase below for what shipped.

---

## Architecture

```
vmw/
├── bin/vmw                 CLI entrypoint (menu + subcommands)
├── main.sh                 thin wrapper → bin/vmw
├── lib/                    shared bash libraries (loaded via lib/init.sh)
│   ├── init.sh             unified bootstrap (sources everything in order)
│   ├── env.sh              VMW_ROOT + ANSI colors
│   ├── log.sh              fmtr::* message helpers
│   ├── log_init.sh         LOG_PATH/LOG_FILE + ROOT_ESC (side effects)
│   ├── prompt.sh           prmt::* interactive prompts
│   ├── config.sh           vmw::load_config / vmw::cfg / vmw::py
│   ├── state.sh            vmw::state / step tracking
│   ├── run.sh              dry-run / plan mode / step runner
│   ├── packages.sh         install_req_pkgs (distro-aware)
│   └── patches.sh          patch version + drift helpers
├── modules/                per-feature scripts (virtualization, qemu, edk2,
│                           vfio, kernel, lg, deploy)
├── python/vmw/             Python tooling package (python3 -m vmw ...)
│   ├── __main__.py         dispatch
│   ├── yaml.py             YAML → flat CFG_* shell assignments
│   ├── state.py            .vmw/state.json manifest manager
│   ├── patches.py          checksum gen/verify + version stamping
│   └── genxml.py           deterministic libvirt XML generator
├── configs/                per-VM YAML profiles (declarative)
│   └── aptwannabe.yml      sample profile
├── patches/                versioned patch artifacts (crown jewels)
│   └── checksums.sha256    patch integrity manifest
├── resources/              helper scripts
│   └── scripts/            SMBIOS.py, vbios dumpers, Windows PS1s
├── scripts/                dev workflows
│   └── add_patch.sh        new-patch workflow (stamp + rechecksum)
├── docs/                   design docs
├── .vmw/                   local state (gitignored)
├── logs/                   runtime logs (gitignored)
└── src/                    build artifacts (gitignored)
```

All paths are derived from `$VMW_ROOT` (resolved in `lib/env.sh`), so scripts
work regardless of the CWD they're invoked from. Python tooling is invoked via
`vmw::py` (sets `PYTHONPATH`) or `PYTHONPATH=$VMW_ROOT/python python3 -m vmw ...`.

---

## Phase 1 — Declarative per-VM config  ✅

Replaced the ~100 interactive prompts with a YAML profile per VM.

- `configs/aptwannabe.yml` — memory, CPU topology, features (Hyper-V/KVM hiding/PMU/SMM/MSRs/PS2), clock, PM, devices (disk/NIC/audio/graphics/TPM), paths, patches, evdev, smbios.
- `python/vmw/yaml.py` (invoked as `vmw::py yaml`) flattens YAML into `CFG_*` shell variables (keys uppercased, `.`→`_`).
- `lib/config.sh::vmw::load_config <profile>` / `vmw::cfg <path>` / `vmw::has_cfg` — portable to bash + zsh.
- `config.xml` is no longer tracked; it's generated output.

### YAML gotcha
YAML 1.1 coerces `on`/`off`/`yes`/`no` to booleans. Any value that must stay a libvirt string is quoted in the profile (e.g. `pmu: "off"`, `loader_secure: "yes"`).

## Phase 2 — Plan mode + idempotency  ✅

- `vmw::dry_run_on/off/p` — global dry-run flag.
- `vmw::run <cmd...>` — prints command in dry-run; executes + logs otherwise.
- `vmw::steps <module> "cmd" ...` — runs command strings, skipping steps already recorded done in the state manifest.
- `python/vmw/state.py` — JSON manifest in `.vmw/state.json`:
  - `done <module> <step>`, `pending <module> <step>`, `has module.<m>.<s>`
  - `set/get <key>` for arbitrary values
  - `reset [module]`, `list [module]`

Resume: re-running `setup` skips completed steps and continues mid-build.

---

## Phase 3 — Patch integrity  ✅

- `patches/checksums.sha256` — generated by `vmw::py patches gen`.
- `vmw::py patches verify` — verifies every patch's SHA256; flags missing/unlisted patches.
- Source-version stamping: `scripts/add_patch.sh <patch> [version]` prepends a `# Source: <version>` header (inferred from filename if omitted) and refreshes checksums.
- `vmw::py patches version <file>` — reads the stamped target version.
- Drift detection in `modules/qemu.sh`, `modules/edk2.sh`, `modules/kernel.sh`: before applying, compare stamped target version vs. the source tag being built; warn + prompt to continue on mismatch.

### Workflow for new/updated patches
```sh
scripts/add_patch.sh patches/QEMU/AMD-v11.0.4.patch v11.0.4
vmw patch-status
```

## Phase 4 — Deterministic XML generation  ✅

`modules/deploy.sh` (611 lines of fragile string-built `virt-install` XML) replaced with a thin wrapper around `python/vmw/genxml.py`.

- Reads the YAML profile → emits a libvirt domain XML with `lxml`.
- Uses `qemu:commandline` for `-smbios file=...` (namespace declared properly).
- Schema-valid: `virt-xml-validate` passes. Fixed schema gotchas during development:
  - `<msrs>` uses `unknown=` attr, not `state=`
  - NVMe disk dev must match `nvme[0-9]+n[0-9]+` (`nvme0n1`)
  - `logical_block_size`/`physical_block_size` live on `<blockio>`, not `<target>`
  - `<audio>` requires `id=`; cdrom target uses `sda` (pattern rejects `sata0-0-1`)
- Wrapper `deploy.sh`: `--print <profile>` (write configs/<profile>.xml), `--dry-run <profile>` (stdout), or default = generate → validate → `virsh define`.

---

## Phase 5 — CLI consolidation  ✅

`bin/vmw` is now both the interactive menu (default) and a CLI:

| Command | Action |
|---|---|
| `vmw` | interactive menu |
| `vmw plan <profile>` | print the full setup plan + generated XML, no execution |
| `vmw setup <profile>` | verify patches → run all modules in order |
| `vmw deploy <profile>` | generate + validate + `virsh define` |
| `vmw patch-status` | verify patch checksums + versions |
| `vmw status` | list profiles, libvirt domains, state manifest |

---

## Out of scope (deliberately)

- Rewriting modules in Go/Python — rejected: single-committer project, ~2,000 commits of working bash; the patches are the value, not the orchestration.
- Migrating kernel/qemu/edk2 build internals to another language.
- Any change to patch *content*.

---

## Rollout / verification

```sh
vmw help
vmw plan aptwannabe          # inspect before executing anything
vmw patch-status             # patch tree integrity
vmw deploy --print aptwannabe  # generate + validate domain XML
virt-xml-validate configs/aptwannabe.xml domain
```
